# 电商协作机器人演示场景和后续规划

本文档用于记录飞书管理员 AI 机器人在电商项目里的演示场景、团队协作价值和后续开发方向。

## 1. 项目定位

本项目不是单纯把 `lark-cli` 包一层壳，而是把个人 Agent 能力产品化成企业飞书里的团队协作入口。

核心目标：

```text
团队成员在飞书里用自然语言提出需求
  ↓
机器人识别业务意图
  ↓
调用受控工具 / lark-cli / 外部电商系统接口
  ↓
拿到结构化结果
  ↓
LLM 整理成用户能看懂的回复、卡片或文档
  ↓
沉淀日志、审计和上下文记忆
```

适合展示的能力：

- 飞书事件接入；
- 多用户同时使用；
- 群聊上下文和用户上下文隔离；
- LLM 多步规划；
- 受控工具调用；
- Skill + CLI 长尾能力；
- 飞书 OpenAPI 调用；
- MySQL 审计和记忆；
- Docker 部署；
- 企业协作场景落地。

## 2. 对比 Codex + CLI 的团队优势

`Codex + CLI` 更适合技术人员个人自动化；本项目更适合团队共享自动化能力。

主要优势：

1. 入口统一：非技术人员直接在飞书群里使用，不需要安装 Codex 或配置 CLI。
2. 过程共享：团队成员能看到谁提出了需求、机器人执行了什么、结果是什么。
3. 权限集中：可以统一做权限分级、审计日志、高风险操作确认。
4. 能力沉淀：常用流程可以做成稳定工具，不依赖某个技术人员临时发挥。
5. 协作闭环：机器人不仅能查数据，还能建群、发通知、生成文档、组织会议。

一句话表达：

```text
Codex + CLI 是个人生产力工具；飞书机器人 + Agent 是团队协作执行平台。
```

## 3. 电商核心业务场景

### 3.1 商品管理

典型需求：

```text
查一下最近 7 天销量最高的商品。
找出库存低于 50 的商品。
帮我生成一批商品卖点和标题。
```

机器人能力：

- 查询商品数据；
- 统计销量、销售额、库存；
- 生成商品运营建议；
- 输出飞书卡片或表格摘要。

### 3.2 订单管理

典型需求：

```text
查一下客户张伟最近一年的订单。
统计今天支付成功但未发货的订单。
找出退款金额最高的前 10 笔订单。
```

机器人能力：

- 查询客户订单；
- 统计订单状态；
- 识别异常订单；
- 通知对应负责人。

### 3.3 库存预警

典型需求：

```text
查一下库存低于 50 的商品，按最近 7 天销量排序。
把缺货风险最高的商品发给采购同学。
```

机器人能力：

- 查询库存；
- 结合销量计算补货优先级；
- 自动生成补货建议；
- 新建缺货处理群或通知采购。

### 3.4 活动复盘

典型需求：

```text
把 618 活动数据整理成复盘文档。
统计活动期间销售额、订单数、退款率和 TOP 商品。
```

机器人能力：

- 查询活动订单；
- 汇总 GMV、订单数、客单价、退款率；
- 生成复盘文档；
- 发给运营群或指定负责人。

### 3.5 客户分析

典型需求：

```text
分析客户张伟的消费偏好。
找出最近一年消费最高的客户。
```

机器人能力：

- 查询客户订单；
- 按类目、金额、频次分析偏好；
- 生成客户画像；
- 给出运营跟进建议。

### 3.6 售后服务

典型需求：

```text
统计最近 30 天退款原因。
找出售后率最高的商品。
帮我生成延迟发货的客服安抚话术。
```

机器人能力：

- 统计售后数据；
- 分析退款原因；
- 找出高风险商品；
- 生成客服话术。

### 3.7 物流履约

典型需求：

```text
查一下超过 24 小时未发货的订单。
把物流异常订单通知仓库负责人。
```

机器人能力：

- 查询待发货订单；
- 识别履约异常；
- 按负责人分组通知；
- 在群里回报处理结果。

### 3.8 团队协作

典型需求：

```text
新建一个蓝牙耳机缺货处理群，把运营、仓库、采购拉进去。
把今天群聊整理成文档，发给测试账号同学。
创建明天下午三点的复盘会议，并邀请运营同学。
```

机器人能力：

- 查询群成员；
- 创建群聊；
- 拉用户和机器人；
- 创建文档；
- 创建日程或会议；
- 发送飞书通知。

## 4. 推荐求职演示场景

建议重点演示以下 5 个场景：

1. 订单异常分析：查出超时未发货、退款、取消等异常订单。
2. 库存预警和补货建议：结合库存和销量给出补货优先级。
3. 活动复盘报告：查询活动数据并生成飞书文档。
4. 客户订单查询和画像分析：按客户名称查询订单并总结消费偏好。
5. 自动协作闭环：根据业务结果自动建群、拉人、发通知、生成文档。

一条完整演示链路可以设计成：

```text
用户：查一下最近一年电商数据里销售额最高的类目，并整理成卡片发到群里。
机器人：查询多维表格 / 电商接口 → 汇总销售额 → 生成飞书卡片 → 回复群聊。

用户：把这个分析结果整理成复盘文档，发给测试账号同学。
机器人：读取上下文 → 创建文档 → 写入分析结果 → 查询测试账号 → 发送文档链接。

用户：新建一个处理群，把运营、测试账号和相关机器人拉进去。
机器人：查询群成员和应用列表 → 创建群聊 → 拉入成员 → 回报新群 chat_id。
```

## 5. 电商系统接入方式

推荐分阶段实现。

### 5.1 第一阶段：Java Tool 直接封装电商能力

先在本项目里增加电商业务工具，例如：

```text
ecommerce.query_orders
ecommerce.query_products
ecommerce.query_inventory
ecommerce.query_refunds
ecommerce.query_customer_orders
ecommerce.create_restock_task
```

执行链路：

```text
用户自然语言
  ↓
LLM 识别电商意图
  ↓
调用 Java 内置 Tool
  ↓
Java 调外部电商 HTTP API 或 MySQL 只读查询
  ↓
返回结构化数据
  ↓
LLM 整理成中文分析结果
  ↓
飞书回复 / 卡片 / 文档
```

注意：不要让 LLM 直接拼任意 SQL。应该由 Java 工具提供受控参数和固定查询。

### 5.2 第二阶段：抽成 MCP Server

当电商工具稳定后，可以把这些能力抽成 MCP Server：

```text
query_orders
query_inventory
query_refunds
create_task
```

优点：

- Codex、飞书机器人、其它 Agent 都能复用；
- 工具协议更标准；
- 电商系统能力和飞书机器人解耦。

缺点：

- 多维护一个服务；
- 权限、部署、日志链路更复杂。

### 5.3 第三阶段：企业级权限和审计

对电商工具增加权限分级：

```text
普通成员：只能查询公开报表；
运营负责人：可以查询订单、生成报告、发通知；
管理员：可以建群、批量通知、创建任务、修改权限。
```

所有工具调用都记录：

```text
谁发起
在哪个群
调用了哪个工具
入参摘要
结果摘要
是否成功
失败原因
耗时
```

## 6. 后续建议开发内容

### 6.1 任务执行看板

新增 `agent_task` 表，记录每次用户请求的生命周期：

```text
任务ID
消息ID
提问人
会话ID
用户原始需求
当前状态：执行中 / 成功 / 失败
当前阶段
开始时间
结束时间
失败原因
```

价值：

- 用户能知道任务是否还在执行；
- 管理员能排查失败任务；
- 面试演示时能展示完整执行链路。

### 6.2 工具调用明细表

新增 `agent_tool_call_log` 表，记录每一步工具调用：

```text
任务ID
步骤号
工具名
入参摘要
出参摘要
是否成功
错误原因
耗时
```

价值：

- 每一步 AI 决策可追踪；
- 外部接口调用可审计；
- 出问题时不用只翻 Docker 日志。

### 6.3 高风险操作确认

这些操作建议强制二次确认：

```text
批量发消息
删除数据
修改权限
转移群主
邀请大量成员
修改审批 / 日程
```

流程：

```text
机器人：检测到高风险操作，请回复“确认执行”。
用户：确认执行
机器人：继续执行上一次挂起任务
```

### 6.4 任务续跑

支持失败后继续执行：

```text
授权失败 → 用户补授权 → 从失败步骤继续
余额不足 → 管理员充值 → 从失败步骤继续
参数缺失 → 用户补充参数 → 从失败步骤继续
```

### 6.5 电商业务插件层

增加稳定 Java Tool：

```text
OrderAnalysisTool
InventoryWarningTool
CustomerOrderQueryTool
ActivityReportTool
AfterSalesAnalysisTool
```

原则：

- 高频核心场景走稳定工具；
- 长尾飞书能力走 Skill + CLI；
- LLM 负责理解意图和总结结果，不直接操作底层数据。

### 6.6 定时任务

适合电商项目的定时任务：

```text
每天 9 点发送经营日报；
库存低于阈值自动提醒；
退款异常自动提醒；
活动结束自动生成复盘；
每周生成客户复购分析。
```

## 7. 日志阅读建议

当前项目日志建议按阶段号阅读：

```text
[阶段1 接收飞书事件]
[阶段2 回复处理中]
[阶段3 外层Agent规划]
[阶段4 工具调用]
[阶段5 SkillCLI规划]
[阶段6 CLI执行]
[阶段7 CLI结果]
[阶段8 回复飞书]
```

默认 `INFO` 只看阶段和摘要；需要排查大模型原文、CLI 原始输出、飞书完整响应时，临时开启 `DEBUG`。

查看普通流程：

```bash
docker logs --tail=300 -f feishu-admin-ai-bot-clean | grep -E "阶段|ERROR|WARN|余额不足|执行失败"
```

开启 DEBUG：

```ini
APP_LOG_LEVEL=DEBUG
```

恢复普通模式：

```ini
APP_LOG_LEVEL=INFO
```
