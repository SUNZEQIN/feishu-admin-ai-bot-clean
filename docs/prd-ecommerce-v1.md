# 电商 MCP 全公司开放 · 产品需求 PRD（V1）

状态：已评审，可开工
日期：2026-10-04
角色：产品经理
配套文档：`docs/test-cases-ecommerce-v1.md`（验收用例）、`docs/ecommerce-demo-roadmap.md`（能力演进）

## 0. 已拍板决策（2026-10-04）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 数据可见范围 | **1A**：普通员工只看聚合 + 脱敏数据；明细只给运营负责人 |
| 2 | 数据源 | **2A**：V1 使用测试数据；真实电商系统对接放到 V2 |
| 3 | 写动作范围 | **3A**：V1 只带「生成飞书文档并发给指定人」；建群、批量通知放 V2 |
| 4 | 试点范围 | **4A**：先 1 个业务群 + 5-10 人跑一周，通过后再全公司可见 |

## 1. 一句话需求

让公司内任何一个飞书用户，都能在单聊或群里用自然语言查询电商经营数据；机器人通过电商 MCP 取真实结构化数据后给出结论。V1 只开放只读查询，加上一条受控的飞书协作动作。

## 2. 背景与现状

| 能力 | 现状 | 全公司可用的差距 |
|---|---|---|
| 电商工具 | 独立 MCP 服务已运行（8090），5 个只读工具 | 数据来自测试库，非真实经营数据 |
| 机器人入口 | 已实现事件接入、消息幂等、多步规划、工具白名单 | 电商开关默认关闭，仅在测试环境验证 |
| 权限 | 只有用户 / 会话级工具白名单 | **缺少岗位分级与数据可见范围** |
| 审计 | 只有应用日志 | 任务表、工具调用明细表尚未建立 |
| 稳定性 | 已有超时、业务线程池、排队话术 | 未做全公司规模并发验证 |

产品判断：当前能力是演示级。直接全公司开放会先踩三个雷 —— **越权看数据、模型编数据、并发打崩**。V1 的目标就是把这三个雷拆掉。

## 3. 用户与场景

| 用户 | 想做的事 | 典型提问 |
|---|---|---|
| L1 普通成员（客服、仓配、财务） | 看自己关心的公开数据 | 「查一下低库存商品」「做一份活动复盘」 |
| L2 运营负责人 | 看明细、拿结论、发给团队 | 「查张伟最近一年的订单，分析消费偏好」 |
| L3 管理员 / IT | 排查失败、管权限 | 查审计表、调整角色名单 |

## 4. 功能范围（V1）

1. 入口：单聊 + 群聊 @机器人，公司内可见
2. 电商只读 5 个工具全量接入
3. 三级权限（L1 / L2 / L3）+ 数据可见范围控制
4. 审计落库：任务表 + 工具调用明细表 + 角色表
5. 失败话术规范化（见 4.5）
6. 一条协作闭环：查数据 → 生成飞书文档 → 发给指定人
7. 数据来源标注：V1 所有回复底部标注「数据来源：测试数据」

### 4.1 权限矩阵

| 能力 | L1 普通成员 | L2 运营负责人 | L3 管理员 / IT |
|---|---|---|---|
| `ecommerce.query_top_products` | 允许（聚合） | 允许 | 允许 |
| `ecommerce.query_low_inventory` | 允许（不含成本价） | 允许 | 允许 |
| `ecommerce.query_activity_report` | 允许（聚合指标） | 允许 | 允许 |
| `ecommerce.query_refund_top_products` | 允许（商品维度） | 允许 | 允许 |
| `ecommerce.query_customer_orders` | **拒绝** | 允许 | 允许 |
| 生成文档并发给指定人 | 允许 | 允许 | 允许 |
| 建群 / 批量通知 | 不做（V2） | 不做（V2） | 不做（V2） |
| 写回电商系统（改价、改库存、发货） | 拒绝 | 拒绝 | 拒绝（V2 再评估） |
| 查审计数据 | 拒绝 | 拒绝 | 允许（数据库只读查询） |

角色来源：`bot_user_role` 表（open_id → role），默认角色为 L1。名单由管理员维护，不依赖模型判断。

### 4.2 脱敏规则（工具层强制，不能由模型决定）

- L1 的回复中不得出现：客户全名、手机号、收货地址、支付流水号
- 客户明细类工具对 L1 直接不可调用，回复统一为权限引导话术
- L1 只看到聚合值：总额、均值、区间、排名；不展示单笔订单金额
- L2 可见客户姓名 + 订单明细，仍不返回手机号与收货地址
- 脱敏在 Java 工具层完成；模型只负责把已脱敏数据组织成中文

### 4.3 审计字段（V1 必建）

`bot_user_role`：`open_id`、`role`(L1/L2/L3)、`remark`、`updated_at`

`agent_task`：`task_id`、`message_id`、`chat_id`、`chat_type`、`user_open_id`、`user_role`、`raw_input`、`intent_domain`、`status`(RUNNING/SUCCESS/FAILED/PARTIAL/WAITING_CONFIRM)、`stage`、`start_time`、`end_time`、`error_code`、`error_msg`

`agent_tool_call_log`：`id`、`task_id`、`step_no`、`tool_name`、`args_digest`、`result_digest`、`success`、`error_code`、`error_msg`、`cost_ms`、`mcp_latency_ms`、`created_at`

权限拦截统一记为 `success=0`、`error_code=PERMISSION_DENIED`，不单独建表，避免多一条链路。

### 4.4 关键流程

```text
用户 @机器人
 → 消息幂等（message_id 去重）
 → 查角色（bot_user_role，默认 L1）
 → 意图识别（电商 domain）
 → 权限校验（角色 × 工具）
 → 调用电商 MCP（超时保护）
 → 结果脱敏 + 空值校验
 → LLM 整理成中文结论（无数据不得给数字）
 → 回复 / 卡片 / 文档
 → 审计落库（agent_task + agent_tool_call_log）
```

### 4.5 失败话术（定稿文案）

| 场景 | error_code | 用户可见文案 |
|---|---|---|
| MCP 不可用或超时 | MCP_UNAVAILABLE | 电商系统暂时不可用，请稍后再试。本次没有取到数据，我不会给估算值。 |
| 无权限 | PERMISSION_DENIED | 这条数据需要运营负责人权限。需要我帮你把开通需求发给管理员吗？ |
| 无数据 | EMPTY_RESULT | 没有查到符合条件的数据。 |
| 意图不明 | INTENT_UNKNOWN | 没听懂要查什么。可以这样说：查低库存商品 / 查某客户的订单 / 做活动复盘。 |
| 排队已满 | QUEUE_FULL | 当前请求较多，请 1 分钟后再试。 |
| 部分成功 | PARTIAL | 已完成：A。未完成：B（原因）。 |
| 待确认 | NEED_CONFIRM | 将要执行：X。回复「确认执行」继续，其他回复视为取消。 |

## 5. 不做范围（V1 明确不做）

- 写回电商系统：改价、改库存、改订单状态、发货
- 对接真实电商系统 / ERP（V2）
- 定时推送：经营日报、库存预警、退款异常提醒（V2）
- 建群、批量通知、批量拉人（V2）
- 部门级数据隔离（V1 全公司同一套数据范围）（V2 评估）
- 管理后台页面（V1 管理员直接用只读 SQL 查审计表）
- 让模型直接写 SQL 或直连数据库（永久不做）
- 公司外部用户、跨租户使用

## 6. 验收标准

正常路径
- 至少 10 个不同用户，在单聊和群聊两种入口都能拿到真实数据
- 5 个工具全部有成功返回
- 端到端成功率 ≥ 98%，P95 ≤ 15 秒

异常路径
- MCP 宕机：60 秒内给出明确失败话术，回复中**不得出现任何数字**
- 无数据：明确说没查到，不得编造或给出近似值
- 同一条消息重放：只执行一次
- 部分成功：说清哪部分成功、哪部分失败

安全边界（系统不得）
- 让 L1 拿到客户明细、手机号、地址、单笔金额
- 在未确认的情况下执行删除、批量通知、清表
- 在失败或降级时报成功

可观测证据
- `agent_task`、`agent_tool_call_log` 字段覆盖率 100%
- 越权尝试有 `PERMISSION_DENIED` 记录
- 三类异常路径各有至少 1 条自动化用例（见 `docs/test-cases-ecommerce-v1.md`）

## 7. 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 数据越权 | 经营数据、客户信息外泄（最严重） | 工具层强制校验角色，不靠提示词；默认 L1 |
| 模型编数据 | 用户拿假数字做决策 | 无工具返回就不输出数字；失败话术明确禁用估算值 |
| 成本随人数线性增长 | 调用账单失控 | V1 先记录每人消耗，V2 加强制额度 |
| MCP 单点 | 整条链路不可用 | 降级话术 + 健康检查，不做假数据兜底 |
| 并发 | 高峰期排队、超时 | 已有队列话术；上线前压测 20 并发 |
| 测试数据被当成真实数据 | 决策依据错误 | 所有回复底部标注「数据来源：测试数据」 |

## 8. 上线节奏与开关

1. 试点：1 个业务群 + 5-10 人（含 1 名 L2），`FEISHU_ECOMMERCE_MCP_ENABLED=true`，工具白名单只放试点群与试点人
2. 一周观察指标：活跃人数、查询次数、意图分布、失败率、拦截次数、生成文档数
3. 通过门槛：成功率 ≥ 98%、P95 ≤ 15 秒、越权 0 次、编数据 0 次、无 P1 故障
4. 通过后：飞书后台将应用可见范围改为全员，放开会话白名单
5. 回滚：`FEISHU_ECOMMERCE_MCP_ENABLED=false` 或恢复可见范围，1 分钟内生效

## 9. 待定与技术债

- 当前电商服务是自定义 HTTP 端点（`/mcp/tools/list`、`/mcp/tools/call`），不是标准 JSON-RPC MCP。V1 不改；V2 若要给 Codex 等其它 Agent 复用再升级协议
- 部门 / 区域级数据隔离未做
- 管理后台未做，权限名单靠数据库维护
