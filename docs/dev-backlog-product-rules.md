# clean-test 产品规则 → 开发/修改清单（后端视角）

- 输入：`docs/product-rules.md`（产品经理，2026-10-04，共 80 条规则）
- 核实方式：逐条对代码核对，不是照抄状态标记；关键项给出证据（文件 + 行/行为）
- 结论：**待做 17 条 + 部分实现 15 条 = 32 条没有代码支撑**，其中 5 条属于「阻断试点」级别

## 0. 总体判断

产品规则把三个雷（越权、编数据、并发打崩）拆成了 80 条规则，方向对。
但代码现状是：**护栏类（入口、超时、闸门、线上开关）基本到位；数据类与证据类（权限分级、脱敏、审计、幂等）缺口集中**。

所以能开发的活儿不是"从头写功能"，而是三件事：

1. **补证据**：审计三表 + 任务状态 + 拦截记录（没有它，试点期出事只能翻 Docker 日志）
2. **补数据边界**：脱敏（判定已完成，脱敏还没做）
3. **补"确认后"的机制**：挂起任务 + 确认只能消费一次
