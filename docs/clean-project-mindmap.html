clean 项目分层思维导图：飞书 Agent 机器人

一句话总览：Controller 快速收消息，AdminAgentService 管业务入口，Orchestrator 管循环，Planner 管决策，ToolRegistry 管安全执行，lark-cli / MCP 管真实工具。

蓝绿：业务服务紫色：Agent橙色：工具/MCP红色：安全稳定灰色：数据对象

一、主链路总图

飞书回调/api/feishu/events
→
Controller收消息/验 token/去重
→
异步业务层后台线程池处理慢任务
→
Agent 循环plan → tool → observe
→
工具执行lark-cli / MCP / OAuth
→
回复飞书文本/图片/表情/卡片

二、按分层看每个类是干嘛的

1. 启动与配置层
FeishuAdminAiBotApplication

Spring Boot 启动入口，负责把整个项目跑起来。

面试说法：应用启动类，加载 Controller、Service、Config 等 Bean。

FeishuProperties

集中承载飞书、LLM、线程池、工具超时等配置。

作用：避免配置散落在业务代码里。

FeishuAsyncConfig

创建专用业务线程池 feishuAgentExecutor。

作用：让飞书回调线程快速释放，慢任务进入后台。

2. Controller 接入层
FeishuEventController

飞书事件回调入口。处理 URL 验证、消息事件解析、message_id 去重、异步投递任务。

重点：它不跑 Agent，只负责快速 ACK。

FeishuOAuthController

飞书 OAuth 授权回调入口。接收 code/state，把 code 交给服务层换 token 并保存。

用于“以用户身份操作飞书”场景。

HealthController

健康检查接口。

用于部署后确认服务是否活着。

3. 飞书事件解析与去重层
FeishuEventParserService

把飞书原始 JSON 转成系统内部的 FeishuMessageEvent。

解析 sender、message、content、mentions。

MessageDedupService

用 message_id 做 30 分钟内去重。

防飞书重复推送，不防用户手动重发。

JsonUtils

JSON 读写工具，对 ObjectMapper 做统一封装。

避免到处手写 JSON 解析异常处理。

4. 业务入口层
AdminAgentService

后台处理一条飞书消息。先处理帮助、处理中表情、授权二维码，再把复杂需求交给 Agent。

它像业务经理：判断走简单回复还是走 Agent 流程。

FeishuOpenApiService

封装飞书 OpenAPI：回复文本、上传图片、回复图片、添加 reaction 等。

让业务层不用直接拼飞书 HTTP 请求。

QrCodeService

把授权链接生成二维码图片。

避免直接把长授权链接发给用户。

LlmErrorUtils

识别大模型余额不足等错误，并转成用户能看懂的中文提示。

避免把底层异常原样丢给用户。

5. Agent 编排与规划层
AgentOrchestratorService

执行 Agent 多步循环：读取记忆 → Planner 决策 → 工具执行 → observation → 再规划。

核心保护：最大 10 步，防止 Agent 无限循环。

AgentPlannerService

真正调用大模型，构造 prompt，让模型输出 JSON 决策。

只允许两类结果：tool_call 或 final_answer。

ConversationMemoryService

保存和读取当前会话的历史消息。

让 Agent 有上下文，但也需要压缩避免太长。

6. 工具注册、安全与执行层
ToolRegistryService

工具统一入口。做工具白名单、权限校验、超时保护，然后分发到具体工具。

关键面试点：LLM 只提意图，Java 负责安全执行。

ToolPermissionService

判断调用者和会话是否允许调用工具。

防止非授权用户或群越权调用能力。

SkillCliExecutorService

执行飞书相关能力：根据 domain 和 goal 调 lark-cli / Skill，完成真实飞书操作。

具体飞书 API 细节应该下沉到这里，而不是塞满外层 Planner。

EcommerceMcpClientService

调用独立电商 MCP 服务：列工具、调业务工具。

电商数据查询/分析不走飞书 CLI，而走 MCP。

FeishuUserScopeMappingService

根据飞书业务域查询需要哪些用户 OAuth scope。

用户明确要求“用我的身份”时才需要。

UserOAuthTokenService

生成授权链接、用 code 换 token、保存/刷新用户授权。

支撑用户身份操作飞书。

7. 数据对象 POJO 层
FeishuMessageEvent

飞书消息事件的内部表示：appId、eventId、openId、chatId、messageId、text、mentions。

FeishuMention

消息里的 @ 人信息。

UrlVerificationResponse

飞书 URL verification 需要返回的 challenge 对象。

UserOAuthToken

用户 OAuth token 数据结构。

UserScopeInfo

某个业务域需要的 scope 信息。

ConversationMemoryMessage

会话记忆中的一条消息。

AgentDecision

Planner 给出的决策：工具调用或最终回复。

AgentRunResult

Agent 整次运行结果：成功/失败、回复、授权链接等。

ToolCall

模型想调用的工具名和参数。

ToolResult

工具执行后的成功状态、说明和结构化数据。

CliStepDecision

CLI 执行过程中的步骤决策对象。

CliCommandResult

CLI 命令执行结果对象。

三、按工具举 3 个场景

场景 1：飞书群/文档/日程操作

工具 cli.run_skill

  1. 用户说：“帮我在本群发一条通知”或“建一个明天 15:00 的日程”。
  2. AgentPlannerService 判断这是飞书内部操作。
  3. Planner 只传粗路由：domain + 完整 goal + 当前 chatId。
  4. ToolRegistryService 做白名单、权限、超时。
  5. SkillCliExecutorService 根据 lark-cli Skill 查 schema 并执行。

边界：外层 Planner 负责“交给谁”，lark-cli Skill 负责“怎么执行”。

场景 2：用户要求“用我的身份”操作飞书

工具 feishu.scope_for_domain + OAuth

  1. 用户说：“用我的身份读取我的云文档”。
  2. Planner 先查询该业务域需要哪些 scope。
  3. UserOAuthTokenService 生成授权链接。
  4. QrCodeService 生成二维码，FeishuOpenApiService 发回飞书。
  5. 用户扫码授权后，FeishuOAuthController 接收回调并保存 token。

边界：默认机器人身份；只有用户明确说“用我的身份”才走用户 OAuth。

场景 3：电商业务数据查询/分析

工具 ecommerce.list_tools / ecommerce.call_tool

  1. 用户说：“查低库存商品”或“分析近 3 个月退款原因”。
  2. Planner 判断这是电商业务，不走飞书 CLI。
  3. 不确定工具名时先调用 ecommerce.list_tools。
  4. 确定工具后调用 ecommerce.call_tool。
  5. EcommerceMcpClientService 请求独立 MCP 服务并返回结构化数据。

边界：飞书是协作平台，电商分析是业务系统能力，二者不要混在一个执行器里。

四、面试 60 秒讲法

clean 项目整体分成接入层、业务入口层、Agent 编排层、工具执行层和外部服务层。飞书消息先进入 Controller，Controller 只做解析、URL 验证、message_id 去重和快速 ACK，避免飞书超时重试。慢任务交给专用业务线程池，由 AdminAgentService 处理帮助、授权、处理中提示等确定性场景。复杂需求进入 AgentOrchestrator，按 plan → tool → observe 循环执行。Planner 只输出结构化 JSON 决策，不能直接执行工具。真正执行由 ToolRegistryService 统一做白名单、权限和超时保护，再分发到 lark-cli Skill 或电商 MCP。核心设计是：LLM 负责规划，Java 负责执行、安全和兜底。

五、你要背下来的分层句

Controller 快速 ACK；AdminAgentService 管业务入口；Orchestrator 管循环；Planner 管决策；ToolRegistry 管安全执行；lark-cli Skill / MCP 管真实操作。
