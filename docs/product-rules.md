## 0. 现状体检：规则缺口清单

| # | 缺口 | 影响 | 对应规则 |
|---|---|---|---|
| 1 | 只有用户/会话白名单，没有岗位分级与数据可见范围 | 全公司开放即越权 | P-01 / P-04 |
| 2 | 审计表未建立 | 出事只能翻 Docker 日志 | O-01 ~ O-03 |
| 3 | 破坏性操作确认后没有"挂起任务"机制 | 用户回「确认执行」后靠记忆重新执行，可能执行偏 | D-07 |
| 4 | 没有意图指纹幂等 | 用户手动重发同一写操作会执行两次 | I-02 |
| 5 | 群聊记忆是群共享，隐私边界未定义 | A 用户的敏感信息可能出现在回答 B 的内容里 | M-03 |
| 6 | 没有用量限额 | 全公司开放后成本不可控 | L-02 |
| 7 | 代码默认值与 `application.yml` 不一致（CLI 步数 8 vs 15、域名 8 个 vs 15 个） | 换环境启动行为会变 | G-06 |
| 8 | 单聊与群聊回复长度/详略差异未定义 | 群里刷屏 | C-03 |

## 2. 身份与授权（A）

| 编号 | 规则 | 状态 | 验收方式 |
|---|---|---|---|
| A-01 | 默认使用机器人身份（应用 token）；只有用户原话出现「用我的身份 / 以本人身份」才走用户授权 | 部分 | 普通提问不弹二维码；说「用我的身份查我的云文档」才弹 |
| A-02 | 需要授权时，必须先说明申请哪些权限，再给二维码；复合任务一次合并申请常见 scope | 部分 | 复合任务只扫一次码；提示含权限摘要 |
| A-03 | 已授权的 scope 不重复申请；token 到期前 600 秒自动刷新 | 已实现 | 重复任务不再扫码；刷新日志可查 |
| A-04 | 授权失败或 token 失效必须明确告知并给出重新授权入口，不得静默失败 | 已实现 | 失效 token 触发重新授权话术 |
| A-05 | 机器人身份做不到的事，必须说明"这件事需要你的身份"，不得假装完成 | 部分 | 用机器人身份执行需个人权限的操作，回复含原因 |
| A-06 | scope 与业务域映射在配置文件中集中维护，不散落在代码里 | 已实现 | `feishu/user-scope-map.json` 覆盖所有白名单域 |

## 6. 破坏性操作闸门（D）

| 编号 | 规则 | 状态 | 验收方式 |
|---|---|---|---|
| D-01 | 破坏性判定只看子命令名（delete/remove/destroy/drop/revoke/clear/cancel）和 `--yes`，不扫参数值 | 已实现 | 文本里含 delete 不算破坏性 |
| D-02 | 模型自己加 `--yes` 等于未确认，必须用户在**原话**里说确认词 | 已实现 | 模型自动加 --yes 时仍被拦 |
| D-03 | 确认词：确认执行 / 确认删除 / 确认删掉 / 我确认 等，其他表述一律不放行 | 已实现 | 非确认词不执行 |
| D-04 | 确认提示必须写清"将要执行什么"（含命令原文） | 已实现 | 提示含具体命令 |
| D-05 | 用户不回复、回复其它内容、超时未确认，一律不执行 | 已实现 | 无确认时真实删除次数为 0 |
| D-06 | `--help` 等只读元命令不拦，保证模型能读到用法 | 已实现 | help 命令不被拦 |
| D-07 | 确认后必须以原任务上下文续跑（挂起任务 + 有效期，建议 15 分钟），不得重新规划成另一个任务 | 待做 | 确认后执行的命令与原提示一致 |
| D-08 | 拦截与放行都必须落日志，可追溯"谁在什么时候试图删什么" | 已实现 | 拦截日志可查 |

## 15. 永久红线（任何版本都不得违反）

1. 不允许模型直接写 SQL 或直连业务数据库
2. 不允许模型自行确认破坏性操作
3. 不允许伪造成功、编造数据、编造 ID
4. 不允许未授权访问他人数据
5. 不允许把 token、密钥、密码写进日志或回复
6. 不允许把公司数据发到公司外
